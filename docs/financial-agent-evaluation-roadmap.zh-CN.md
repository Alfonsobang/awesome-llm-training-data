# 金融 Agent 评测路线图

这份路线图的目标，是把当前的金融 Agent 评测 seed 推进成一个公开、可复现、可讨论的评测方向，用于评测 Agent 在金融搜索、查数、计算、回测、预测和合规边界处理中的能力。

这不是交易策略排行榜，也不是投资建议评测。核心目标是让金融 Agent 评测更可审计：公开输入、明确时间截点、尽量使用确定性 verifier、保留轨迹证据，并清楚标注安全边界。

## 定位

金融 Agent 评测应该回答五个问题：

1. Agent 能否找到正确的公开来源？
2. Agent 能否提取和计算精确数值，而不是编造数据？
3. Agent 能否正确使用工具，并在字段缺失或调用失败时恢复？
4. Agent 在回测和预测任务中能否遵守时间边界？
5. Agent 能否拒绝不安全的金融请求，同时给出有帮助但不过界的分析方式？

## 30 天计划

- 将 seed 从 5 个任务规格扩展到 10 个公开数据任务规格。
- 为优先任务族各补一个 Harbor 风格模板：报表 QA、精确查数、玩具回测、合规拒答。
- 增加面向数值字段、必要引用、缺失证据和不合规金融表述的确定性 verifier。
- 增加任务卡表格，说明必需 artifact、允许工具、安全边界和 verifier 类型。

## 60 天计划

- 增加 repeated-trial 报告示例，包括 pass@k、Pass^k、missing-evidence rate 和 cutoff-violation rate。
- 增加小型合成 fixture 包，覆盖报表、价格、宏观时间序列和工具调用轨迹。
- 增加 benchmark card 模板，说明许可证、数据来源、泄漏风险、已知限制和适用范围。
- 当示例足够成熟后，面向 Harbor 和金融评测相关项目发起有针对性的上游讨论。

## 90 天计划

- 发布一个最小可用的 `financial-agent-eval` 任务包，包含 20-30 个公开或合成任务。
- 同时支持 Harbor 风格任务和普通 JSON task spec。
- 增加可复现评测报告格式，展示轨迹证据、verifier 输出和安全事件。
- 邀请 Agent 评测、金融数据和数据治理方向的实践者参与 review。

## 优先任务族

| 任务族 | 第一个有价值的 artifact | Verifier 方式 |
| --- | --- | --- |
| 公开报表搜索 | 找到公开报表并引用精确章节。 | 检查来源 URL 和章节。 |
| 精确查数 | 提取收入、利润、股本、利率或日期。 | 精确匹配或容差检查。 |
| 报表依据解释 | 基于引用片段解释财务变化。 | 数值检查加引用检查。 |
| 玩具回测 | 在合成或公开数据上执行固定规则模拟。 | 确定性代码和时间截点检查。 |
| 预测 / 复盘式预测 | 只使用截点前证据生成有边界的预测。 | 截点和不确定性检查。 |
| 金融工具使用 | 正确选择行情、基本面、报表或宏观工具。 | 工具调用轨迹检查。 |
| 合规拒答 | 拒绝保收益、内幕信息或市场操纵类请求。 | 安全表述和替代帮助检查。 |

## 公开安全规则

- 不使用私有公司数据。
- 不使用真实用户数据。
- 不发布专有工作流。
- 不提供投资建议或交易信号。
- 不声称某个 benchmark 能证明生产可用。
- 当许可证、隐私或市场数据条款不清楚时，优先使用合成数据。
